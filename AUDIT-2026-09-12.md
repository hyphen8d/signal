### H2 · Guide index `[1-9]` jump throws past the band's station count

`program.js:3100`:
```js
if (this.guidePage === 2 && /^[1-9]$/.test(e.key)) { this.guidePage = 2 + Number(e.key); this.drawGuidePage(s); return }
```
`drawGuidePageStation` then reads `this.bandPresets()[i].glyph` off
`undefined`. YM has 8 public stations, ZM has 6, and the footer advertises
`[1-9] JUMP`. Reproduced: `[G]`, `[->]`, `[9]` → `TypeError: Cannot read
properties of undefined (reading 'glyph')` out of the key handler,
`guidePage` left at 11 of 10. On ZM `[7]`/`[8]`/`[9]` all throw.

**Fix:** bound `n` by `bandPresets().length`, else no-op (or `closeGuide`,
matching an arrow that cannot move). Test on both bands.

### H3 · Async player events paint through the weather card and the LINE INPUT card

Two holes, same class as the 29th- and 69th-pass fixes recorded in
`drawPlayback`'s own comment:

- `ui/desktop.js:1035` `if (!this.poweredOn || this.guideOpen) return` —
  `setPlayState` arrives from YouTube's `onStateChange`, outside `frame()`'s
  bail. Reproduced: weather consent card open, track ends, 1.2s later row 14
  reads `[····] 0:00 / 3:34  > PLAYING` where `[Y] ALLOW  [N] NOT NOW` was —
  the two keys that answer the card are gone. LINE INPUT card row 14 likewise.
- `showTrack`/`showStation`/`clearTrack`/`clearStation` have no overlay guard,
  and `resolveText` (`ui/desktop.js:632-633`) paints its first tick
  synchronously before handing the rest to the gated `fxEvery`. So under any
  overlay, ENDED → `skip()`, `onError` → `skip()`, or the scan timer →
  `tryLock()` (the scan deliberately keeps running under the weather card)
  lands one frame of `▓▒░#%&*` on the card that never settles or clears.
  Reproduced on all three overlays; scan locking under the weather card
  leaves rows 9, 10 and 13 as noise.

**Fix:** one `overlayUp()` predicate (`guideOpen || tapConsentOpen ||
weatherOpen`) used by `drawPlayback` and the four show/clear methods (keep
`updateTabTitle` running). Every close path already rebuilds from state via
`redrawLockState`, so nothing is lost. Test: open each overlay, `endTrack()`,
advance, assert the overlay rows are byte-identical.

### H4 · BREACH's resolve words have never rendered

`visuals/breach.js:85-113`: the per-column loop draws column x's rain and
then, in the same iteration, writes `col.word` horizontally across
x..x+len. Iterations x+1, x+2, … repaint every row of their own column,
overwriting every character but the first. Measured over 400 frames on
CIPHER: **0 intact / 9482 broken** (`SYN` → `"SF6"`, `AUTH` → `"A  6"`). The
effect's design hook ("a short span occasionally RESOLVES — holds a legible
fragment for a beat", lines 43-51) has been invisible since it was written;
the 65th pass doubled the resolve chance on a pulse and doubled nothing
anyone could see.

**Fix:** draw the rain loop to completion, then a second pass for words.
Then see M5 — fixing this alone surfaces the frozen-word bug it has been
masking.

### H5 · A dead-video skip on any ZM station leaves the tube at full degrade for the rest of the lock

`crt-hooks.js:120` `const { dist } = nearestSignal(s.program.freq)` — no
band, defaults to YM. On a ZM frequency (≥1000) the nearest YM carrier is
≥100 units off, `pct` saturates, and the 150ms "restore" writes `chroma 0.9 /
snow 0.035 / roll 0.5`. Nothing reapplies `setCrtDegradation` until the next
`retune()`. Reproduced: lock THE CRYPT, `h.player.fail()`, params go from
crtBase to the off-station maximum and are still there 6s later. Same class
as audit L1 (`applySecretTease`); this was the last band-less tuning call in
the tree (`crtIdleEvent`/`crtGrind` in `ui/desktop.js` both pass the band).

**Fix:** `nearestSignal(s.program.freq, s.program.band)`, plus a test that
fails a track on ZM and asserts params return to crtBase.

### H6 · `[0]` / `[)]` lock a YM secret station while the dial stays on ZM

`program.js:3115/3127` `presetTune(s, NIN_STATION)` with no band check;
`retune` clamps 613 into ZM's range. Result: `mode=locked, lockedStation=nin,
band=zm, freq=1000` — readout says 1000.0, tuner box says ZM BAND, dial cursor
at the left edge, SIG meter and hiss computed off ZM's nearest carrier, red
tint up. Breaks the "a station on the other band is unreachable" invariant
`cycleBand` exists to keep. Persistence is not corrupted only because secret
stations never restore.

**Fix:** a preset knows its band — in `presetTune`, if `station.band !==
this.band`, make the three moves `cycleBand` makes (band, `drawChrome`,
`drawScale`), the same "band follows the station" rule `?station=` already
applies (~`program.js:560`). A real dual-band set's preset button switches
the band.

## MEDIUM

### M1 · A track that dies during the preset sweep is never skipped — STATION BREAK forever

`onError` (`program.js:1391`) opens with `if (self.mode !== 'locked')
return`. `presetTune` → `enterSeeking` → `_primeStationAudio` cues the incoming
track while `mode` is `'seeking'` for ~330ms; a cue error in that window is
dropped. `tryLock` then sees `primedFresh` and does not reload, so the dead
video stays in the player, no PLAYING arrives, `detectBreak()` trips at 4s
and `STATION BREAK -- <CALLSIGN> RETURNS SHORTLY` holds indefinitely with
`playState=buffering`. Only a manual `[N]` recovers. Reproduced.

**Fix:** in `onError`, if `_primedTrack` is fresh, count it against
`_errorSkips`, `flashCrtGlitch`, and re-prime with a fresh `nextTrack()` draw
(re-running `_primeStationAudio` is not enough — `_pickTrackFor` can hand the
same remembered dead track back inside RESUME_CUTOFF_MS); keep the bail for a
genuinely unlocked set.

### M2 · Double-pressing a preset inside its own sweep corrupts the departing station's resume position

`presetTune` early-returns only when `mode === 'locked' && lockedStation ===
station`. On the second press `mode` is `'seeking'`, so it snapshots
`lastPlayback[old.id]` again — now reading `getCurrentTime()` off the freshly
cued incoming track (the B2 shape the 2026-09-02 fix closed for `tryLock`) —
and draws a second bag entry. Reproduced: old station at 202.9s, remembered
position after the double press = 77.5s, bag advanced by 2, three cues.
`cycleBand` during a sweep has the same snapshot problem (~`program.js:2530`).

**Fix:** treat a fresh prime for the same station as the debounce case; guard
both snapshots with the `primePending` test `tryLock` already uses.

### M3 · Sleep timer expiring under the weather card leaves `weatherOpen` true through STANDBY and the next power-on

`sleepExpired` (`program.js:2025`) closes the LINE INPUT card and the guide,
not the weather card; `powerDown` never touches `weatherOpen` (its only
writers are `ui/weather.js:78/99` and `init`). After expiry the STANDBY clock
never ticks; after `[P]` the boot completes and `redrawMainScreen` paints a
normal screen with no card, but `frame()` bails, the fx queue is frozen,
`isMappedKey` is false for everything and `key()`'s weather branch eats every
press. The visitor sees an ordinary locked set that ignores the keyboard.
Reproduced.

**Fix:** clear `weatherOpen` in `powerDown` beside `visualizerActive` (and/or
`if (this.weatherOpen) this.closeWeather(s)` in `sleepExpired`).

### M4 · One exception in the frame path kills the picture permanently while audio plays on

`src/screen.js:52-80`: the next `requestAnimationFrame` is the last statement
and neither it nor `program.frame()` has a guard. One throw from any visual's
`draw`, a weather redraw or the game step (H2 is one such throw, from a key
handler — but the same shape) ends the rAF chain: tube frozen on the last
frame, YouTube playing, the 250ms fallback ticker draining fx into a grid
nobody rasterises, the `#fault` panel never shown. This is E1's "set with a
dead tube", reachable from an ordinary JS error rather than a context loss.

**Fix:** `try { … } finally { this.raf = requestAnimationFrame(…) }` with a
`console.error` in a catch — or stop and show `#fault` from the catch the
way `webglcontextlost` does. Pick one; a silent freeze is the worst of the
three.

### M5 · Three visuals carry absolute effect-clock state across re-entry

The FLAME-class bug (`reset` must re-arm clocks because the effect clock
restarts at 0), three more times:

- **BREACH** `visuals/breach.js:38-42` — `reset()` zeroes only
  `_breachLastT`; `col.resolveAt` and `col.wordUntil` survive. After a 120s
  visit, exit, re-enter: 30/80 columns hold a word that stays lit BRIGHT
  until t climbs back past ~120s, 55/80 have no ambient resolve for minutes.
  Invisible today only because of H4.
- **RIPPLE** `visuals/ripple.js:28-32` — no `reset()`; slots' `startT` are in
  the future after re-entry (9/11 measured), skipped and never respawned; the
  line-75 safety net keeps exactly one ring alive so it reads as "rain almost
  stopped".
- **DREAD** `visuals/dread.js:61` — no `reset()`; a tear active at exit (~9%
  of frames) re-enters as a full-row BRIGHT strobe held until the old
  `until`, blocking every new tear.

**Fix:** `reset()` in each: clear words and set `resolveAt = -1` (BREACH);
re-seed `startT`/`amp` (RIPPLE); `tear.active = false` (DREAD).

### M6 · Power-off does not cut an in-flight voice clip

`cutLiveVoice()` (`audio/voice.js:163`) is module-private; `powerDown()`
stops the bed, the hum, the player and the duck but not the speaker bus or
the live voice. A station ID (~2.4s) or liner (up to 8.5s) that started
before `[P]` keeps announcing over STANDBY. The existing guards only stop a
clip that has not started.

**Fix:** export `stopLiveVoice()` (fade via `cutLiveVoice(audioCtx())`), call
from `powerDown()`; arguably from `tryLock()` too so a stale ID never names
the wrong station.

### M7 · Boot prefetches and decodes every clip on disk — 4.3MB per visit, per stamp

`program.js:240-244` prefetches the welcome line, every station ID and every
liner. That is ~45 mp3s, ~4.3MB, re-downloaded on every stamp bump because
`clipUrl()` cache-busts, decoded into ~45 PCM `AudioBuffer`s held for the
session, on mobile too. The 55th/56th-pass comment predates the roster
growing from 9 clips to 45.

**Fix:** prefetch the welcome line and the locked station's ID/liners on
lock; let the rest load from `maybePlayLinerDrop`'s 2.5s window.

### M8 · A shielded RAM breaks the chain, against the design record in two places

**Fix:** if `g.shield > 0`, don't book the escape (leave the enemy alive —
the 40-step invuln carries the ship past it). Ram-path test.
