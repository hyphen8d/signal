## MEDIUM

### M1 · Per-station phosphor decay is lost on power-up and in the visualizer — CONFIRMED

`visualizer.js:13` and `program.js:27` destructure `crtBase` from a dynamic
import. `crtBase` is an `export let` that `setCrtCharacter()` *reassigns*, so
both modules hold the boot-time `{...SCREEN}` snapshot forever (decay 0.75).
- `program.js` ~1136: every power-up writes 0.75, so DRIFT MODE, NEON STASIS,
  GREEN ROOM (0.88) and ATOMIC (0.7) lose their persistence on a cold boot
  until the first retune.
- `drawVisualizerFrame` (visualizer.js ~423) writes the stale 0.75 every frame
  for effects without their own `decay` — an override, the opposite of the
  "a floor, not an override … DRIFT MODE's 0.88 keeps it" comment.
  `restoreTubeDecay()` on exit/power-off restores 0.75 too, so the dial stays
  wrong after [E].
- Harness: NEON STASIS 0.88 after retune → 0.75 in [V] → 0.75 after exit.
- Missed because `visual-flame.test.mjs` uses DISTORTION FIELD, whose decay
  equals SCREEN's. `ui/desktop.js:12` has the same snapshot (`rollSpeed`),
  harmless today since no station sets it.
- Fix: read through the namespace or a `getCrtBase()`; test on a 0.88 station.

### M2 · The screen-reader announcer lies or goes quiet in three ways — CONFIRMED

- `program.js:1037`: `announce('Receiver on.')` runs *above* the
  `poweredOn || _powerAnimating` guard. [P] during the 500ms cold-open
  flourish or the 130ms collapse says "Receiver on." with the set still off,
  and the real power-on that follows is then deduped into silence.
- `a11y.js:27`: the per-kind memory is never cleared. Power off → on to the
  same station announces only "Receiver on." (station and track suppressed —
  `program.js:1037`'s "the station follows once it locks" is false); detune
  one step and re-lock announces nothing; losing a lock is never announced.
- `adjustVolume` (~1883) un-mutes silently, so M → ↑ → M announces "Muted."
  once and the second mute says nothing.
- Fix: announce below the guard; `forget(kind)` from clearStation/clearTrack/
  powerDown; announce the un-mute in `adjustVolume`.
- Related test bug: `tests/a11y.test.mjs:70` compares station objects to ids,
  so it always presses `1` and passes only because CITY LIGHTS isn't preset 1.

### M3 · A stalled health sweep can be hidden by any flag — CONFIRMED

`tools/roster-watch.mjs:91-93` (`classify`) checks `unconfirmed`/`findings`
before `throttled`, and `bumpStreak` (:109-113) zeroes `incomplete` for any
other outcome. With one strike-1 row, six throttled days in a row simulated as
`unconfirmed`, `{incomplete:0}`, notify=false every day — the "unfinished run
reads as fine" failure the tool exists to prevent. Same with a confirmed
finding, which is the live state right now. Fix: bump `incomplete` whenever
`summary.throttled`, regardless of label.

### M4 · Health-watch strike bookkeeping has four holes

- **Daily critical nag, no ack** (`roster-watch.mjs:99`): a confirmed finding
  notifies every day until fixed, and a deliberately kept track (an accepted
  narrow licence) would forever — the wallpaper the header warns against.
- **Flagged-first can starve the sweep** (`check-roster.mjs:81-92`): flagged
  rows take a batch slot every run forever; at ≥40 flagged (a channel or
  station-wide licence change) nothing else advances, and `sweepMargin`
  doesn't count them. Oldest record is already ~18 days against a 30-day
  horizon. Cap flagged slots (~25%).
- **UNVERIFIED drops a flag off the alarm for ~19 days**
  (`check-roster.mjs:82, 168-181, 296-303`): strikes are held, but `flags`
  becomes UNVERIFIED, so `nextBatch` stops ranking it first and `summarise`
  stops counting it. One truncated non-throttle probe hides a dead track for a
  full pass.
- **No time spacing**: a dashboard re-probe minutes after an `unconfirmed` run
  confirms a transient; strikes also add across different flag types.
- Smaller: the `findings` notification counts and lists strike-1 rows
  (`roster-watch.mjs:154-160`); the dashboard watch strip has no `unconfirmed`
  case (green dot, grey pip — `network.html:1309-1325`).

### M7 · Volume 0 and the sleep timer can blip to full level — call order CONFIRMED, audibility PLAUSIBLE

#67 made `applyVolume()` own un-muting, but five callers still `unMute()`
first (program.js ~1319 reveal, ~1687 loadTrack, ~1886 toggleMute, ~3082 key
flush; ui/mobile.js:490). Per the harness's captured model, `unMute()` restores
the remembered level (100 on a fresh player), so a session saved at VOL 0
sends `unMute → setVolume(0) → mute` at the reveal. Separately, `powerDown()`
clears the sleep fade and the duck *before* `pauseVideo()`, so an expiring
sleep timer sends `setVolume(2) → unMute → setVolume(70) → pauseVideo` — a
possible full-level blip at the one moment meant to be quiet. Settle by ear:
save at VOL 0, reload, power on; and let a 15-min sleep run out.

### M8 · The degauss can fire on the wrong gesture — PLAUSIBLE

`audio/sfx.js:649-661`: the cold-open flourish queues
`ctx.resume().then(scheduleDegauss)` at page load. The comment assumes
Chromium never settles it; per spec, pending resume promises resolve at the
first gesture that unlocks audio. If that gesture is [G], the coil thunk plays
in STANDBY, and the 30s re-arm then eats the real [P]'s degauss. Settle by
ear: cold load, press [G] first.
