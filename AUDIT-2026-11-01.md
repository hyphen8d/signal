## MEDIUM

### M1 · The reduced-motion default only applies on the first visit — CONFIRMED

`state.js:63` saves `panel` whole; `init` fills `this.panel` with defaults, so
the first save from **any** action ([C], a lock, volume) persists all four
rows, including `screen`. Afterwards `normalizePanel(saved.panel, …)`
(`program.js:579`) always prefers the saved row over `prefers-reduced-motion`.
So an OS reduce-motion switched on after the first visit is ignored, and a first
visit made under reduce-motion stays CALM for good. On mobile there is no card to
undo it. The comment at `state.js:57` covers the case it was written for (a visitor
who *chose* FULL must stay FULL). It doesn't separate that from a row nobody touched.
Repro: boot, power, [C], read payload (`screen:"full"`), reboot with
`reducedMotion: true` → `screen full`, flicker 0.075.
`rear-panel.test.mjs:224` hand-writes its saved payload, which is why the tests
miss this. Fix: persist only rows set through `setPanelOption` (e.g. a
`panelSet` list); untouched rows fall back to `defaultPanel()` each load. Test
with a payload the app wrote.

### M2 · Ctrl/Cmd+R opens the rear panel instead of reloading — CONFIRMED (harness)

Nothing in `key()`, `isMappedKey()` or `src/screen.js` reads
`ctrlKey/metaKey/altKey`. Since #92, `case 'r'` (`program.js:3746`) calls
`preventDefault`, clicks, and opens the card; the browser reload is lost while
the set is on. The same is older for Ctrl+P (power, blocks print), Ctrl+C (tint,
blocks copy), Ctrl+F (fullscreen, blocks find). Fix: return early from `key()`
and `isMappedKey()` on ctrl/meta/alt (keep Shift: Shift+C/T/0 are real).
A 10-second check in a live tab would confirm that the browser actually cancels the reload.

### M3 · The health watch can't see a takedown for up to ~20 days

H2 is the case: `verify` caught three 404s in one cheap pass while the deep
probe's rotation still lists them OK. A takedown (oEmbed 404) is exactly what the
cheap oEmbed check sees and the batched deep probe reaches last. Suggest:
`roster-watch` also runs an oEmbed sweep of the whole roster each day (743
lightweight requests, a different endpoint from the throttled watch page) and
pushes any 404 to the front of the deep-probe queue, or flags it directly with
the same confirm-twice rule.

### M4 · `ship.mjs verify` can say LIVE while skipping files — CONFIRMED

`tools/ship.mjs:362` finds "the previous deploy" with
`git log -n 2 origin/main -- build.json`. History simplification walks the PR side
of the merge, so a branch stamped twice (a re-run `ship pr` after review fixes)
yields its own un-deployed first stamp. Every app file changed before that
stamp then drops out of the byte comparison. Reproduced in a scratch repo:
`changedAppFiles()` returned `['other.js']` and missed `app.js`. Fix:
`--first-parent`; add the shape to `ship.test.mjs`.
